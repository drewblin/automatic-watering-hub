# Окремі параметри автоматичного поливу для кожної зони

## Задача

Дати кожній зоні власні пороги вологості ґрунту, максимальну тривалість
одного поливу та паузу перед повторним автоматичним запуском. Нині всі
чотири значення спільні для зон у `GlobalSettings`. Зміни стосуються ПЗ і
не потребують нових компонентів PCB.

## Налаштування та сумісність

- Для зони з датчиком вологості зберігати відсоток вологості для початку
  поливу й відсоток для зупинки. Для кожної зони зберігати максимальну
  тривалість одного поливу в секундах і мінімальну паузу перед повторним
  запуском у секундах.
- Відображати й змінювати ці значення через інтерфейси налаштувань.
  Повернення налаштувань має однозначно прив'язувати значення до зони.
- Для прив'язаної до датчика зони перевіряти, що пороги лежать у межах
  0–100 % і поріг початку менший за поріг зупинки. Для всіх зон перевіряти,
  що тривалість і пауза додатні та не перевищують допустиму межу для
  часових налаштувань.
- Під час оновлення перенести чинні спільні значення в кожну вже
  налаштовану зону, щоб поведінка поливу не змінилася без рішення
  користувача. Для нових зон задати зрозумілі початкові значення. Описати
  сумісність формату налаштувань для клієнтів API.

## Логіка поливу

- Для зон із датчиком починати, зупиняти й повторно запускати
  автоматичний полив за власними порогами та часовими значеннями.
  Для зон без датчика застосовувати запуск за розкладом і критерій
  завершення з [задачі 14](14-sensorless-scheduled-watering.md).
  Зберегти правило одного активного зонального клапана в автоматичному
  режимі.
- Загальне часове вікно поливу й обмеження часу ручного відкриття клапана
  залишити окремими загальними налаштуваннями. Окремі календарні графіки
  зон і цільовий обсяг води до цієї задачі не входять.
- Для зон із датчиком дотримуватися перевірки свіжості показів і аварійної
  реакції датчика з [задачі 10](10-soil-sensor-freshness-fail-safe.md).

## Критерії приймання

- Дві зони з різними порогами вологості, тривалістю та паузою працюють
  незалежно одна від одної.
- Після оновлення контролера наявні зони отримують колишні спільні
  значення й зберігають свою попередню поведінку.
- Некоректні значення окремої зони відхиляються під час збереження
  налаштувань; після перезапуску коректні значення зберігаються.
